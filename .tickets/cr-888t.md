# Fewer dependencies: replace crates with our own code where it is safe (plan written, NOT started)

User decisions (2026-11-09): the goal is FEWER DEPENDENCIES (not offline builds); priority P1. The plan is written here; do not start it until the user says go.
Agent reading (tentative, reversible): with this goal, copying crate source into vendor/ is not needed, so the "35 MB of vendored source in git" question no longer applies. If offline builds are wanted later, `cargo vendor` can be added as a separate step.

**Today** (Cargo.lock at commit 464396d; `cargo tree -e normal`): 8 direct dependencies, 49 crates besides crane-rs. Release binary 1.71 MiB (aarch64-apple-darwin).

| Direct dep | Crates it brings (incl. shared) | What crane uses it for |
|---|---|---|
| ureq 3.5.1 (rustls) | 22: ureq, ureq-proto, http, httparse, bytes, base64, log, once_cell, percent-encoding, utf8-zero, itoa + TLS: rustls, ring, rustls-webpki, rustls-pki-types, webpki-roots, untrusted, subtle, zeroize, getrandom, libc, cfg-if | HTTP/1.1 client (src/client.rs only) |
| clap 4.6.7 | 10: clap, clap_builder, clap_derive, clap_lex, anstyle, heck + proc-macro chain syn, quote, proc-macro2, unicode-ident | 13 subcommands, a few flags (src/cli.rs) |

**Per crate: what to do and why** (crates removed = from the tree above; shared crates stay while anything else needs them)
1. tar -> own ustar code (src/tarfmt.rs, about 150 lines: reader with GNU/PAX long names, writer we already shape). Removes tar, filetime (2). Risk low: fixture and cross tests cover both directions.
2. clap -> hand-written parser (about 300 lines). Removes clap, clap_builder, clap_derive, clap_lex, anstyle, heck (6). Cost: help, usage and parse-error text become ours; keep go crane's flag names, exit code 1 and `Error: ...` on stderr; golden tests for help and errors.
3. serde derive -> hand-written field reading over serde_json::Value, and a small JSON writer for the one built manifest (types::docker_manifest_bytes; go escaping of < > &). Keep serde_json: never hand-roll a JSON parser for untrusted registry input. Removes serde, serde_derive (2), and with step 2 the whole proc-macro chain syn, quote, proc-macro2, unicode-ident (4) -> much faster clean builds.
4. ureq -> own blocking HTTP/1.1 client on std::net + rustls (StreamOwned), reusing the server's parser (src/registry/http.rs). Removes ureq, ureq-proto, http, httparse, bytes, base64, percent-encoding, utf8-zero (8; we already have our own base64 and percent encoding), and log if rustls builds without its logging feature. What we must then own: redirects (drop Authorization on a redirect to another host, as ureq does today), chunked and Content-Length responses, a keep-alive pool (perf gate), timeouts, and proxy support only if crane needs it (check whether anything relies on HTTPS_PROXY first). Highest effort; do it after 1-3.
5. sha2 -> optional, decide last: own SHA-256 with std::arch (ARMv8 SHA2 and x86 SHA-NI) plus a portable fallback, about 300 lines with unsafe. Removes sha2, digest, block-buffer, crypto-common, hybrid-array, typenum, const-oid, cpufeatures (8). Checks: NIST test vectors, cross digests (real tarball digest), perf gate. Recommendation: keep sha2 unless the count still matters after 1-4.
6. Keep: anyhow (1 crate, no deps), libc (ring and getrandom need it anyway), serde_json and its 4, and the TLS stack (rustls, ring, rustls-webpki, rustls-pki-types, webpki-roots, untrusted, subtle, zeroize, getrandom, cfg-if, once_cell). Never hand-roll TLS. webpki-roots is a frozen Mozilla root list we must keep updated.

Expected floor after 1-4: about 19 crates (from 49); 27 if sha2 stays. Estimates from today's tree; each step records the real number.
